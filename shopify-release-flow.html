Content-only release

Proposal

Used when the merchant needs to publish content and there is no code to release. It is a separate process from the normal release, with an entry condition.

The merchant edits the [Store] - Content theme → the App commits to the content branch
Check the diff

Until the next normal release: main differs from production by content files only. That is why the "empty diff" check applies after a normal release, not after this one. Recording it in RELEASES.md is an open decision.
3

Update content after a release

Proposal

After a release or hotfix that put code on production. Without it, the Content theme is missing the new sections and blocks. Not needed after a content-only release.

TriggerA release (or hotfix) with code is on production
1Create chore/sync-content-<date> from origin/content
2git merge origin/production

The source is always production. Never staging, development or main, so unreleased code never reaches the merchant's theme.
